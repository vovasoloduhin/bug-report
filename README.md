# Bug-Report

```bash
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt   # тепер включає Pillow для аватарок
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

## Можливості
- **Профіль** — «Мій профіль» у меню або клік по імені/аватарці будь-де. Статистика: скільки багів знайшов, скільки виправив (призначені на нього баги зі статусом «Виправлено» або «Закрито»), що зараз у роботі, коментарі, розподіл знайдених багів за важливістю, відсоток виправлених. Чужий профіль бачать лише учасники спільних команд, і статистика рахується лише за спільними командами. Аватарка завантажується в «Редагувати профіль»: обрізається до квадрата 256×256, перекодовується в WEBP, віддається лише авторизованим (`/accounts/avatar/<id>/`).
- **Запрошення за посиланням** — «Команди → команда → Запросити за посиланням». Термін дії, ліміт використань, зона нового учасника, скасування.
- **Пошук і теги** — рядок пошуку у списку багів (назва, кроки, результати, коментарі, теги, номер `BUG-12`), фільтр за тегом, теги задаються при створенні/в картці бага.
- **Права** (на учасника): «Може закривати баги» (статуси «Закрито» / «Не буде виправлено») і «Може керувати складом» (запрошення, додавання/видалення, зміна зон і прав). Власник має все; право керувати складом видає лише він.
- **Живі сповіщення** — сторінка сама опитує сервер кожні 5 с, показує спливайку, оновлює лічильник і грає звук (перемикач у лівому меню).
- **Видалення багів** — іконка кошика в рядку списку або кнопка «Видалити» в картці бага. Видаляє автор бага, власник команди і той, кому дали право закривати баги. Разом із багом зникають коментарі, історія, сповіщення та файли вкладень, а теги без багів прибираються. У списку рядок зникає без перезавантаження.
- **Права панель** на сторінці списку: зведення (відкриті, термінові, вирішені, розподіл за статусами), «Мені призначено» та остання активність. Оновлюється сама, коли приходить нове сповіщення або видаляється баг.

## Як працюють вікна, що спливають без перезавантаження
1. `base.html` кладе на `<body>` атрибути `data-poll` (адреса опитування) і `data-last-id` (id останнього сповіщення, яке користувач уже бачив; його дає `bugs/context_processors.py`).
2. `static/js/notifications.js` кожні 5 с (15 с, якщо вкладка у фоні) робить `fetch('/notifications/poll/?after=<id>')`. Це простий polling, без WebSocket.
3. `bugs.views.notifications_poll` повертає JSON: кількість непрочитаних і нові сповіщення з id більшим за `after`.
4. Для кожного нового елемента скрипт створює DOM-вузол спливайки (`BT.toast` у `static/js/app.js`), додає його в `#toasts` (позиція `fixed` у куті), CSS-анімація показує його, через 10 с або по кліку на хрестик він зникає. Текст вставляється як текст, тому HTML у повідомленнях не виконується.
5. Далі оновлюється лічильник у меню й заголовок вкладки, грається звук (Web Audio) і генерується подія `bt:notifications`. На неї реагує `app.js`: підтягує HTML правої панелі (`/bugs/panel/`) і тіло таблиці й підміняє їх на місці.
6. Видалення працює так само: кнопка відкриває діалог `<dialog>`, після підтвердження йде `fetch POST` на `/bugs/<id>/delete/` із заголовками `X-CSRFToken` та `X-Requested-With`, сервер відповідає JSON, рядок зникає з таблиці. Без JS форма на сторінці бага працює як звичайний POST із редіректом.
